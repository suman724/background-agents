# Run Locally — Cheatsheet

One-page command reference for running the full Open-Inspect stack on your laptop.

First time here? See the longer [Local Development guide](./LOCAL_DEVELOPMENT.md) which walks
through GitHub App / OAuth App setup. This page assumes setup is already done.

## TL;DR

```bash
nvm use          # picks up .nvmrc → Node 22
npm install      # only if you pulled
npm run dev      # localhost   OR
npm run dev:lan  # bind to 0.0.0.0 for cross-machine browser access
```

Wait for three colored prefixes:

```
[daemon] [sandbox-daemon] listening on http://localhost:9000
[cp]     [wrangler:info]  Ready on http://0.0.0.0:8787
[web]    ✓ Ready in NNNms
```

Open http://localhost:3000. Ctrl-C kills everything.

## Per-step commands

If `npm run dev` fails or you want to drive a single piece on its own:

| Step | Command                                 | Purpose                                                                               |
| ---- | --------------------------------------- | ------------------------------------------------------------------------------------- |
| 1    | `npm run dev:bootstrap`                 | Idempotent. Generates `.dev.vars` and `.env.local` with random secrets on first run.  |
| 2    | `npm run dev:build:sandbox`             | Idempotent. Builds `openinspect/sandbox-runtime:dev` (cached layers after first run). |
| 3    | `npm run dev:migrate`                   | Idempotent. Applies D1 migrations to local SQLite.                                    |
| 4a   | `npm run dev:sandbox-daemon`            | Long-running. Localhost only, never LAN.                                              |
| 4b   | `npm run dev:control-plane` (or `:lan`) | Long-running.                                                                         |
| 4c   | `npm run dev:web` (or `:lan`)           | Long-running.                                                                         |

The `dev` and `dev:lan` aggregators run 1→3 in sequence then 4a/b/c concurrently with prefixed
colored output.

## Endpoint checks

```bash
curl -s http://localhost:9000/health                                       # {"ok":true}
curl -s http://localhost:8787/health                                       # {"status":"healthy","service":"open-inspect-control-plane"}
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000             # 200
```

For LAN mode replace `localhost` with your LAN IP for the last two (the daemon stays localhost-only
by design).

## What needs real values

`npm run dev:bootstrap` leaves these placeholders in your env files. Without them the agent flow
won't work end-to-end:

| Variable                                       | Lives in                           | Source                                                                             |
| ---------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------- |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`    | `packages/web/.env.local`          | OAuth App at https://github.com/settings/applications/new                          |
| `GITHUB_APP_ID` / `GITHUB_APP_INSTALLATION_ID` | `packages/control-plane/.dev.vars` | GitHub App at https://github.com/settings/apps/new                                 |
| `GITHUB_APP_PRIVATE_KEY`                       | `packages/control-plane/.dev.vars` | Generated by the GitHub App, **then `openssl pkcs8 -topk8 -nocrypt`** before paste |
| `LOCAL_DOCKER_OPENCODE_AUTH_PATH`              | `packages/control-plane/.dev.vars` | Created by `opencode auth login` (preferred — OAuth)                               |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`         | repo secrets (via dashboard)       | Provider console (fallback — static keys; some orgs forbid)                        |

See [LOCAL_DEVELOPMENT.md §3-§4](./LOCAL_DEVELOPMENT.md#one-time-setup) for the step-by-step.

## Common gotchas

- Browser spins forever over LAN → set `NEXT_DEV_ALLOWED_ORIGINS=<LAN-IP>` in `.env.local`.
- `/repos` returns 500 → GitHub App credentials missing or PEM not PKCS#8.
- "No migrations to apply!" → not an error. Migrations already ran; D1 file is at
  `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/<hash>.sqlite` (hashed name is wrangler's, not a
  bug).
- `npm run dev` fails with "engine unsupported" → run `nvm use` first.

Full troubleshooting list in [LOCAL_DEVELOPMENT.md](./LOCAL_DEVELOPMENT.md#troubleshooting).
